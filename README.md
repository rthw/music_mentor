# music_mentor

Наставник по музыке и Ableton Live для [pi](https://pi.dev) (модель DeepSeek). Он читает твои проекты
Ableton (Live 10, 11 и 12), считает по нотам теорию — тональность, аккорды, ритм, диапазоны — и объясняет
по-русски, что в треке происходит и что можно сделать дальше.

Проект в работе: готовы чтение проектов `.als`, мост к запущенному Live (`bridge/MentorBridge`,
`extensions/live.ts`) и установщик для Windows (`install.ps1`, `update.ps1`, `change_key.ps1`).

## Что умеет сейчас

Пишешь обычным текстом, наставник сам вызывает инструменты:

- «Какие у меня есть проекты?» — `project_list`: ищет `.als` в Документах (в том числе в OneDrive) и на рабочем столе;
- «Что в этом проекте?» — `project_summary`: темп, размер, треки, устройства, клипы;
- «Покажи ноты клипа» — `clip_notes`;
- «Что тут с гармонией и ритмом?» — `project_analysis`: тональность, аккорды по тактам, бас, ритм, диапазоны, энергия;
- «Что я изменил с прошлого раза?» — `project_diff`;
- «Я записал, как играю руками — как получилось?» — `play_check`: сравнение попытки с клипом-целью
  (пропуски, не та высота, опоздание в мс, ровность, разнобой в аккордах), если Live открыт — берёт
  последнюю запись на треке;
- «Давай потренируем слух» — `ear_next`/`ear_answer`: задание звучит в твоём же Live (трек «Подсказка:
  Слух») — интервал, мажор/минор, ступень аккорда из твоей последовательности, изменившаяся нота баса,
  диктант из 2–4 нот по твоему треку. Отвечаешь словами или игрой; правильный ответ агент узнаёт только
  при проверке, поэтому не подсказывает.

- «Почему мой трек звучит мутно?» / «Сравни с референсом» — `audio_list`/`audio_analyze`/`audio_compare`:
  экспортируешь трек в WAV (File → Export Audio/Video), наставник считает на твоём компьютере громкость
  (LUFS, true peak, LRA), баланс по полосам, стерео, спорит ли бас с бочкой — и называет одно действие в
  Live твоей версии. Это цифры, а не слух: решают твои уши. mp3 не читается (перетащи его в Live и
  экспортируй в WAV). Сам звук никуда не уходит — к модели идёт короткая сводка.

Проект при этом не нужно открывать в Live, и ничего в нём не меняется: файл только читается.

## Windows 7 (серверный режим)

На Win7 pi не ставится, поэтому он работает на сервере, а у ученика — PuTTY и мост (`tools/vps/`, `docs/spec.md` §7b).
Автор заводит ученика одной командой `tools/vps/new_learner.sh <имя> --host H --port P` и отдаёт ему zip
(`install_win7.cmd` + `README.txt` на три-пять шагов).

## Агент растёт

Три пути, от лёгкого к тяжёлому; всё лежит в `learner/` рабочей папки и переживает обновление:

- **Рецепты** (`recipe_save`): удачный приём или упражнение агент записывает маленьким скиллом в `learner/recipes/`
  (сработало или «запомни»; без дублей: похожий рецепт обновляется). pi видит папку как скиллы — `skills` в
  `settings.json` ставят установщик и обновление.
- **Свои функции** (`my_tools_save`, `my_tools_admin`): только по просьбе ученика агент дописывает расширение pi в
  `learner/my_tools/` (локальный пакет в `packages`). После записи отдельный pi проверяет, что оно загружается, иначе файл
  откатывается. Аварийный выключатель: `start_mentor.cmd` при падении pi в первые секунды зовёт `lib/mm/guard.ts`,
  тот выключает пакет (метка `learner/my_tools_disabled`), строка «Мои функции выключены…» и повторный запуск.
  «Выключи мои функции» / «почини мои функции» — `my_tools_admin`.
- **Заявки автору** (`wish_send`): агент составляет заявку, показывает её дословно и отправляет только после «да» ученика
  на `present.whimsical.work/api/wish`. Приёмник — `tools/wish/wish_receiver.mjs` (user unit `wish_receiver.service`,
  Caddy `tools/present/Caddyfile` проксирует `/api/*`): токен, ≤ 4 КБ, 5 заявок в сутки на адрес, отброс мусора, пересылка в
  Telegram через `tg-send`, журнал на хосте. Нет сети — заявка ждёт в `learner/wishes.md`, повтор на старте сессии не
  чаще раза в сутки.

## Запуск

Нужны [pi](https://pi.dev) и Node.js 22.18 или новее.

```sh
pi install <папка или git-адрес этого репозитория>
cd <рабочая папка>
pi
```

Проверка кода: `npm test` (зависимостей ставить не нужно).
Поведение наставника на девяти сценариях: `secret run DEEPSEEK_API_KEY -- tools/eval/run.sh`
(изолированный `HOME` и `PI_CODING_AGENT_DIR`, фикстуры, ответы вне репозитория) —
см. [tools/eval/README.md](tools/eval/README.md).

## Установка и обновление (Windows)

Другу отправляется одна строка (её собирает автор: `tools/invite.sh`), она запускает `install.ps1` с тега
последнего релиза: Git, Node и pi нужных версий, код, ключ, рабочая папка, ярлыки, мост к Live.
Каждый шаг идемпотентен — повторный запуск ничего не ломает.

- Версии (тег релиза, версия pi, минимальный Node) лежат в одном файле —
  [`lib/win/versions.json`](lib/win/versions.json): установщик читает его по сети с того же тега,
  `update.ps1` — с диска после `git checkout`.
- `update.ps1` (ярлык «Обновить наставника» или `mentor_update`) догоняет версии pi и Node, ставит код и
  обновляет рабочую папку: файлы наставника (`AGENTS.md`, скиллы) перезаписываются, а `learner/` и
  `notes/` — твои, они только создаются и никогда не перезаписываются.
- Всё, что видно в окне, плюс текст ошибок пишется в `%LOCALAPPDATA%\music_mentor\logs\<скрипт>_<дата-время>.log`
  (последние 10 файлов). Ключ DeepSeek в журнал не попадает. При ошибке установщик печатает путь и
  кладёт файл в буфер обмена: его и надо прислать автору. Наставник читает журнал сам — инструмент
  `mentor_log`.
- На старте сессии наставник кладёт в первый ход сводку (`extensions/session_start.ts`, собирает её
  `lib/mm/briefing.ts`): профиль и статусы тем, 1–3 свежих проекта, что изменилось с прошлого снимка,
  идею из последней строки журнала, предупреждения о новой версии и балансе ключа (их отдаёт
  `extensions/update.ts`, проверка не чаще раза в сутки). Нет сети — молчит.
- Баннер «Update Available» в pi выключен: ярлык пишет `set "PI_SKIP_VERSION_CHECK=1"` — версию pi двигает
  `update.ps1` по `versions.json`, а самообновление сломало бы закреплённую версию.

Выпуск версии у автора: `tools/release.sh 0.1.1` — только план, `tools/release.sh 0.1.1 --yes` —
тесты, правка версий, коммит, тег и push.

## Мост к Live

`bridge/MentorBridge/` — Remote Script (Python 2.7 для Live 10 и 3.x для Live 11/12, один код), порт 127.0.0.1:9878.
Положить папку `MentorBridge` в `<User Library>\Remote Scripts`, перезапустить Live и один раз выбрать MentorBridge в
Settings → Tempo & MIDI (Live 11 и старше 12.4: Link, Tempo & MIDI; Live 10: Link MIDI) → Control Surface, Input/Output None.
Мост только читает проект и добавляет свои треки «Подсказка: …» и клипы в пустые слоты; менять и удалять
существующее он не умеет (проверка в коде моста). Тесты моста: `tests/bridge/README.md`.
