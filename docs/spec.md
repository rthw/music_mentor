# music_mentor — спецификация

v0.1, 2026-11-08. Карта работы — тикет T1602 в `agent_memory/inbox`. Здесь подробности. Решения из
этого документа меняют только с новой датированной строкой в разделе «Журнал решений» в конце.

## Зачем

Подарок другу: агент-наставник по музыке. Он смотрит в проект Ableton, помогает улучшать треки или
начинать с нуля, отвечает «как это сделать в Live» и сам ведёт по теории. Сам определяет уровень
ученика и следующий шаг. Нужен баланс трёх вещей: **удовольствие от своей музыки**, **рост знания**,
**качество трека**.

## Ученик

- Windows (10 или 11, точнее неизвестно), Ableton Live **10, 11 или 12**, редакция неизвестна
  (Lite/Intro/Standard/Suite). Max for Live может не быть.
- Музыку уже делает, теорию почти не знает. Интересы: что-то оркестровое плюс «электроника, но не
  типичная». Стиль ещё не сложился: агент **выясняет его сам** по проектам и разговору, не навязывает жанр.
- С агентами почти не работал. Всё ставится и настраивается автоматически. От него требуется только
  писать по-русски обычным текстом, без слэш-команд и конфигов.
- Модель — только DeepSeek. Она **не видит картинок и не слышит звук**, поэтому агент никогда не просит
  скриншот или аудио, а смотрит сам: файл `.als` и мост к Live.

## Что окажется у него на компьютере

```
Ярлыки на рабочем столе: «Музыкальный наставник», «Сменить ключ DeepSeek», «Обновить наставника»
          │
          ▼
Windows Terminal → pi (DeepSeek) в папке Documents\music_mentor   ← рабочая папка ученика
   ├─ расширения music_mentor: als (чтение проектов), live (мост), session_start, web, guard, ask
   ├─ скиллы: mentor, theory, ableton, project
   └─ knowledge/ (банк знаний, читается grep/read)
          │ TCP 127.0.0.1:9878 (JSON-строки)
          ▼
Ableton Live 10/11/12 + Remote Script MentorBridge (Python 2.7 и 3 одним кодом)
```

Рабочая папка ученика: `AGENTS.md` (роль и правила), `learner/profile.md`, `learner/log.jsonl`,
`learner/snapshots/` (сводки проектов для diff), `notes/` (его заметки и упражнения).

## Репозиторий

Публичный `github.com/rthw/music_mentor`. Без ключей и текстов книг: только выжимка своими словами
со ссылками на страницы (см. «Банк знаний»).


## 1. Установщик `install.ps1`

Запуск — одна строка в PowerShell, которую автор присылает другу (см. §2):

```powershell
$env:MM_KEY='<ключ>'; irm https://raw.githubusercontent.com/rthw/music_mentor/v0.1.0/install.ps1 | iex
```

Ссылка всегда указывает на **тег релиза**, а не на `main`: так кэш raw.githubusercontent не подсунет
старую версию (урок pi_home).

Шаги. Каждый идемпотентен, повторный запуск пропускает сделанное:
1. Проверки: версия Windows, PowerShell 5.1+, свободное место, сеть. `Documents` — через
   `[Environment]::GetFolderPath('MyDocuments')`, потому что у многих она перенаправлена в OneDrive.
2. Git for Windows (pi нужен Git Bash): `winget install Git.Git -e --silent`. Нет winget или он
   упал — свежий установщик по API релизов `git-for-windows/git`, файл ищется **по шаблону**
   (`Git-*-64-bit.exe`), а не по имени.
3. pi: способ выбрать по факту на чистой Windows (winget `EarendilWorks.pi` или Node LTS через winget +
   `npm install -g --ignore-scripts @earendil-works/pi-coding-agent@<версия>`), версию pi закрепить.
4. Код music_mentor: `git clone --depth 1 --branch <тег>` в `%LOCALAPPDATA%\music_mentor\app`,
   затем `pi install` этого пути. GitHub-аккаунт не нужен.
5. `settings.json` pi: provider deepseek, модель по умолчанию `deepseek-v4-pro` (запросов мало, важнее
   качество; flash остаётся в списке), `quietStartup`, `shellPath` при необходимости, Shift+Enter
   в Windows Terminal (pi docs: terminal-setup).
6. Ключ (§2) → `%USERPROFILE%\.pi\agent\auth.json`. Сразу проверка запросом баланса.
7. Рабочая папка `Documents\music_mentor` из `template/`. Если она уже есть, не перезаписывать.
8. MentorBridge (§4) в каждую найденную установку Live.
9. Ярлыки: «Музыкальный наставник» (`wt.exe -d <папка> pi`; нет Windows Terminal — окно PowerShell),
   «Сменить ключ DeepSeek», «Обновить наставника».
10. Самопроверка: `pi --version`, баланс ключа, `project_summary` на встроенной фикстуре, `live_ping`
    (если Live открыт). В конце — короткий итог по-русски и одна инструкция: «включи MentorBridge
    в Preferences, наставник подскажет как».

Правила (из истории pi_home, обязательны):
- **Ни одного молчаливого выхода.** Каждый шаг в `try/catch`. При ошибке — «Шаг N (<имя>) не
  получился: <текст>. Сфотографируй это окно и пришли <автору>». Никакого `exit` без сообщения.
- Не прописывать жёстко имена файлов релизов: пакетный менеджер, иначе поиск по шаблону и
  архитектуре с понятной ошибкой.
- Лишних зависимостей нет: GitHub CLI, вход в GitHub, Python и админ-права не нужны. Права
  администратора (UAC) — только для Live 10 старше 10.1.13 (§4).
- Кириллица: файл в UTF-8 с BOM, проверить вывод в PowerShell 5.1 через `irm | iex`.
- Готовность — **полный прогон на чистой Windows 10 и 11**, а не проверка одной строки.

Обновление: ярлык или инструмент `mentor_update` → `git fetch --tags`, checkout последнего тега,
`pi install`. `session_start` раз в день проверяет новый тег и говорит о нём одной строкой.

## 2. Ключ DeepSeek

- В репо ключа нет и никогда не будет.
- Автор заводит **отдельный ключ** для друга (его можно отозвать, не трогая свой) и кладёт его
  в `secret set deepseek_music_mentor`.
- `tools/invite.sh` у автора: `secret run` → собирает строку установки из §1 и кладёт её **в буфер
  обмена** (`wl-copy`), не печатая в терминал. Автор отправляет её другу и потом удаляет сообщение.
- Без `MM_KEY` установщик сам просит вставить ключ (ввод скрыт).
- Замена: ярлык «Сменить ключ DeepSeek» → `change_key.ps1`: вставить → проверка балансом → запись
  в `auth.json`. Работает и `/login` в pi, но другу про него знать не нужно.
- Баланс: `session_start` проверяет `GET https://api.deepseek.com/user/balance`. Мало денег —
  предупреждение. Ошибка 402 (баланс кончился) — понятная фраза «деньги на ключе закончились, напиши
  <автору>» вместо стека ошибки.

## 3. Чтение проекта: `extensions/als.ts` + `lib/music`

`.als` — XML в gzip. Читается без запущенного Live в любой версии, поэтому это **основной способ**
смотреть проект. Мост нужен только для «сейчас в Live» и для записи.

Инструменты:
- `project_list` — `.als` в Documents, на рабочем столе и в папке проектов из настроек Live. Без
  `Backup\` и `Ableton Project Info`, сортировка по дате изменения.
- `project_summary(path)` — версия Live (`Creator`), темп, размер, тональность и лад (Live 12),
  локаторы, длина аранжировки; треки (тип, имя, цвет, mute, цепочка устройств с понятными именами:
  `InstrumentVector` → Wavetable, `OriginalSimpler` → Simpler, VST — имя плагина), клипы в Session
  и Arrangement (имя, позиция, длина, число нот), аудиоклипы (имя сэмпла). Компактный текст:
  проект из 20 треков укладывается в ≤ 4 КБ.
- `clip_notes(path, track, clip)` — ноты клипа (питч с именем ноты, start, duration, velocity).
- `project_analysis(path)` — метрики из `lib/music` (ниже), по секциям, если есть локаторы.
- `project_diff(path)` — что изменилось с прошлого снимка в `learner/snapshots/` (новые треки,
  клипы, устройства, ноты). На нём строится «вижу, вчера ты добавил…».

`lib/music` — детерминированный код, LLM его только комментирует (принцип из music_workbench):
- тональность по профилям Крумхансла с весом по длительности: глобально и по секциям;
- аккорды по долям и тактам: трезвучия, септаккорды, sus, обращения; ступени относительно тональности;
- ноты вне тональности, хроматизмы;
- бас против корней аккордов, параллельные квинты и октавы между крайними голосами
  (как сведения о стиле, не как «ошибка»);
- ритм: плотность, сетка квантования, синкопы, разброс velocity;
- регистр и диапазон трека против типовых диапазонов инструментов (оркестровых тоже), «грязные»
  интервалы в низу (терция ниже ~E2 и т.п.);
- фактура: число одновременных голосов, расположение (тесное/широкое);
- форма и энергия: сколько треков звучит в каждом 8-тактовом блоке, границы секций.

Метрики дают «признаки» для узлов учебного дерева (§5): например, «использует септаккорды» или
«бас ходит не только по корням».

Различия форматов 10, 11 и 12 (ноты, `KeyTracks`, `NoteId`, вероятность в 11+, `ScaleInformation` в 12)
закрываются фикстурами всех трёх версий.

## 4. Мост MentorBridge

Remote Script. Основа — AgentBridge автора (`agent_tools/win_live/remote_script/AgentBridge`):
сокет-поток только кладёт строки в очередь, LOM трогается только из `update_display()` в главном
потоке; одна строка JSON → одна строка ответа; исключение в команде не роняет скрипт. Порт **9878**
(не 9877, чтобы не пересекаться с AgentBridge на тестовой VM).

Python 2.7 (Live 10) и 3.x (Live 11/12) одним кодом: без f-строк и аннотаций,
`try: import queue / except ImportError: import Queue as queue`, `io.open`, без `os.replace`.
Шимы по `hasattr`: ноты — `get_notes_extended/add_new_notes` (11+) или `get_notes/set_notes` (10);
`arrangement_clips` нет в Live 10, тогда Arrangement читается из `.als`.

Установка (§1, шаг 8): версии Live — по `C:\ProgramData\Ableton\Live *` и
`%APPDATA%\Ableton\Live x.y.z\`. Live 10.1.13+ и новее — в `<User Library>\Remote Scripts\MentorBridge`
(путь User Library — из `Library.cfg` в папке настроек Live), без админа. Live 10 старше 10.1.13 —
в `<Live>\Resources\MIDI Remote Scripts\` через UAC. Ставится в одно место, не в оба (иначе в списке
будут два пункта).

Включение — единственный ручной шаг: Preferences → MIDI / Link, Tempo & MIDI → Control Surface →
MentorBridge, Input/Output None. Агент видит, что Live запущен, а порт закрыт, и ведёт по шагам
с названиями вкладок **его** версии. После этого проверяет `live_ping`.

Команды:
- чтение: `ping` (версия Live и моста), `song` (темп, размер, play, лад в 12, выбранные
  трек/сцена/клип), `tracks` (треки, устройства, клипы в слотах), `clip_notes`, `browser`
  (инструменты, эффекты и пресеты, которые **есть в его редакции**);
- запись **только добавлением** (решение автора 2026-11-08):
  - `add_midi_track {name}` — трек с префиксом «Подсказка: » и фиксированным цветом;
  - `add_clip {track, slot, length_beats, notes, name}` — только в **пустой** слот: на треке-подсказке
    или на его MIDI-треке (чтобы вариант звучал его звуком); имя клипа с префиксом «Подсказка: »;
  - `load_device`, `set_param` — только на треках-подсказках;
  - `remove {track}` — только трек-подсказку и только после «да» в чате;
  - воспроизведение (`fire_clip`, `stop`) — только по его просьбе.
- Запрет проверяется **в коде моста**, а не в промпте: изменить или удалить существующий клип,
  ноту, устройство, параметр или микшер на его треках — `ok:false` с объяснением.
- Перед первой записью за сессию `live.ts` копирует текущий `.als` в
  `learner/backups/<дата>_<имя>.als`. В чате агент напоминает, что всё отменяется Ctrl+Z.
- Лимиты редакций (в Lite и Intro ограничено число треков) — понятная ошибка, а не стек.

## 5. Банк знаний

Выжимка своими словами, по-русски. Тексты книг в репо не кладутся.

**Учебное дерево** `knowledge/curriculum.yaml`: 40–60 узлов в ветках:
- Основы: ноты, интервалы, лады, тональность;
- Ритм и грув;
- Гармония: трезвучия → функции → последовательности → септаккорды → модуляция и хроматика;
- Мелодия и голосоведение: мотив, фраза, контур, басовая линия, голосоведение, контрапункт без строгости;
- Форма и аранжировка: предложение и период, секции, развитие, кривая энергии;
- Тембр и оркестровка: регистры, удвоения, оркестровые группы и диапазоны, слои в электронике,
  основы синтеза;
- Сведение и мастеринг (базово).

У каждого узла: `id`, уровень 1–5, `prereq`, **признаки в проекте** (метрики `lib/music`), упражнение
в Live на 5–15 минут, источники.

**Карточки** `knowledge/cards/<ветка>/<id>.md`, по одной на узел, 300–600 слов: суть; почему так
работает (восприятие, Huron); где и как это нарушают (Tymoczko, поп, кино); как услышать и сделать
в Live (с пометками для 10/11/12); упражнение; источники (`книга, с. N`); не больше двух цитат по
1–2 предложения.

**Ableton** `knowledge/ableton/<задача>.md`: около 50 частых «как сделать» с различиями версий 10/11/12
и ссылкой на страницу официального мануала его версии. Если в банке ответа нет — `web_fetch` мануала.

Источники:
- 12 книг автора (индекс `music_books` в music_workbench): Aldwell, Huron ×2, Tymoczko, Schubert ×2,
  Caplin, Moore, Senior, Izhaki, Katz;
- открытые: *Open Music Theory* (CC BY-SA 4.0, можно адаптировать с атрибуцией; такие карточки
  лицензируются CC BY-SA), Римский-Корсаков *Основы оркестровки* (общественное достояние) — под его
  оркестровый интерес;
- мануалы Ableton 10/11/12: только пересказ и ссылки.

Пайплайн `tools/distill/` (работает только у автора, где лежат книги): узел → запросы → `music_books
search/page` → модель пишет карточку → проверки. Модель — параметр, по умолчанию Sonnet.
Детерминированные проверки в `npm test`: у каждой карточки есть источники и страницы, цитаты ≤ 2
и ≤ 40 слов на карточку, совпадение 8-грамм с исходными страницами ниже порога (оценка пишется
во фронтматтер карточки при генерации). Выборку из 10 карточек сверяет со страницами сильная модель
до массовой генерации.

## 6. Наставник: модель ученика и ход сессии

Скилл `mentor` + `AGENTS.md` рабочей папки.

**Первый запуск.** Знакомство, не больше 5 вопросов по одному (инструмент `questionnaire`): как зовут;
что любит слушать (2–3 примера); что хочет (доделать трек, научиться, просто кайф); сколько обычно
времени на сессию. Версию Live и редакцию агент узнаёт сам (`.als`, `ping`) и сам смотрит 2–3 свежих
проекта. Итог — гипотеза уровня в `learner/profile.md`.

**Модель ученика** `learner/profile.md`: интересы, цели, что нравится, версия и редакция Live; по
каждому узлу дерева статус «не встречал / видел / пробовал / владеет» с доказательством (проект и
дата, или «объяснил своими словами»). «Владеет» — признак встречается в двух и более проектах или
он применил это сам без подсказки. `learner/log.jsonl` — строка на сессию: что делали, что
получилось, идея на следующий раз.

**Старт сессии** (`session_start.ts` кладёт в контекст первого хода): свежие проекты и `project_diff`
с прошлого раза, выжимку профиля, идею из прошлого лога, баланс ключа, новую версию (если есть).
Агент начинает с **конкретного наблюдения про его музыку** («в «Ночи» появились струнные в низком
регистре…») и предлагает три пути: улучшить этот трек / начать новый / разобраться в чём-то. Плюс
одной строкой «следующий шаг», который советует он сам.

**Правила баланса:**
- сначала музыка, потом термин: теория всегда привязана к его нотам и трекам;
- не больше **одной новой идеи теории** за ответ и одного нового узла за сессию;
- следующий узел — тот, чьи `prereq` в статусе «пробовал» или выше, который связан с текущим
  треком и его интересами (зона ближайшего развития);
- «Analyze → Explain → Suggest → User chooses»: 1–2 варианта с ценой, решает он; его ноты не трогаем,
  варианты кладём клипами-подсказками;
- «ошибку» не называем ошибкой: объясняем эффект и где так делают («в строгом стиле так нельзя,
  потому что…, а в кино-музыке…»);
- упражнение — в его треке и в Live, 5–15 минут;
- хвалить конкретно: что сработало и почему;
- захотел просто кайфовать — не грузить теорией, отложить идею в «на потом»;
- «как сделать в Live» — пошагово меню и кнопками **его** версии и редакции, без устройств, которых
  у него нет;
- по-русски, на «ты», коротко; термин при первом появлении — с объяснением.

**Конец сессии** (он прощается или долго молчит): резюме в 2–3 строки и запись в `log.jsonl`,
обновление `profile.md`.
